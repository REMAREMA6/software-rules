## Evidence inspected

- `src/jwt/verify.ts`: `jwtVerify` verifies compact JWS signature before validating the JWT Claims Set.
- `src/lib/jws_verify.ts`: explicit `algorithms` allowlist is checked before signature verification.
- `src/lib/jwt_claims_set.ts`: issuer/audience required-claim and matching rules, temporal `exp`/`nbf` semantics, fixed-clock option, and optional-claim behavior.
- `test/jwt/verify.test.ts`: upstream tests for issuer/audience, algorithm allowlists, expiration, not-before, and claims validation.

## Selected bounded rule

Verify HMAC-signed compact JWTs using an explicit HS256 allowlist, fixed verification time, configured issuer, and configured audience. Probe valid/invalid signatures, algorithm rejection, expiration, not-before, issuer/audience mismatch and absence, optional expiration, and audience-array matching.

## Independent replica

A Python 3.12 verifier using only `hmac`, `hashlib`, `base64`, and `json` is prepared under `conformance/replication-lab/projects/jwt-auth-python/`. It verifies the exact compact token strings generated by the pinned jose runtime.

## Boundary

This is a token-verification case, not a complete identity provider or login/session lifecycle. RSA/ECDSA, remote JWKS, revocation, refresh tokens, JWE, and authorization policy are excluded.

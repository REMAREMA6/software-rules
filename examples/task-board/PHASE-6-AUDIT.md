# Task Board — Phase 6 evidence audit

**Date:** 2026-11-26  
**Status:** Initial audit completed; additional runtime probes remain active  
**Related:** [Phase 6 programme](../PHASE-6-FACET-EXPANSION.md), [Task Board fixture](README.md)

## Purpose

Review the existing Task Board capture claims against the actual observation records, evidence records, runtime harness, and integrity validator. This is a correction of the initial baseline, not a claim that the Task Board now captures every software facet.

## Findings

### Interface

- The initial retained interface observation records geometry and resolved presentation values for the main controls, and explicitly labels its own completeness as partial.
- The Playwright harness records full computed CSS maps, pseudo-element content, DOM hierarchy, geometry, accessibility snapshots, semantic attributes, and screenshots for its enumerated states. Its archive is linked by digest and can be regenerated by the committed harness, but the hosted artifact expires after 30 days.
- The capture inventory previously marked font rendering as covered separately while having no explicit property for it. The inventory now includes ui-font-rendering as required and partial. A single Chromium/Linux capture does not establish fallback and glyph-rendering behaviour across broader font/runtime conditions.
- External media assets remain marked not applicable for this fixture, based on the inspected application content. This does not mean all asset-related UI properties are irrelevant to other software.

### Behaviour and functionality

The existing runs provide real examples for create, complete, filter, delete, keyboard operation, blank/whitespace submission, and one HTTP 503 failure. They do not exhaust the operations' boundary, repeated, concurrent, malformed-input, or failure cases.

### Business rules

The previous inventory had no business-rules facet. The existing evidence supports only partial samples:
- whitespace-only submission is ignored;
- a newly created task is observed as incomplete;
- the summary changes from one active task to zero active after completion.

It does not establish the complete title policy, duplicate-title policy, count rules for multiple mixed tasks, or other possible constraints.

### Data

The previous inventory had no data facet. The API adapter provides partial samples of a task record with id, title, and completed, and one PATCH response preserves the title while changing completion. One record is insufficient to establish identifier generation/uniqueness, nullability, optional fields, validation constraints, or all update semantics.

### API and system boundary

The API evidence is generated by a deterministic in-memory Playwright route adapter. It demonstrates client/adapter exchanges, not production server, network, authentication, persistence, or external integration behaviour.

### Integrity validation

The existing integrity validator verifies identifier uniqueness, reference resolution, target/facet consistency, and whether declared statuses conflict with a complete result. It does not inspect whether the linked evidence content actually supports the claimed property, nor whether the property inventory omits relevant rules. Passing this validator is therefore not a semantic completeness proof.

## Corrections made

All three captures now include:
- one additional partial interface property for font rendering;
- partial business-rule observations for title/blank handling, initial completion state, and summary counts;
- partial data observations for task record shape, identifier generation, and PATCH field-preservation semantics.

After the first audit, each capture had 29 entries with seven partial properties. The successful expanded probe run then supplied evidence for six of those properties and added four captured properties plus one new partial title-length property. Each capture now has 34 entries: 28 captured, two partial, one not applicable, and three optional exclusions. All three still report replication-scope completeness as incomplete.

The equivalent and deliberate-difference comparison reports now use incomplete-both. Their observed agreement or mismatch findings remain useful, but neither report claims replication completeness.

## Probe execution result

The expanded Playwright probe suite passed in [GitHub Actions run #45858743131](https://github.com/REMAREMA6/software-rules/actions/runs/45858743131). It captured title trimming, duplicate-title acceptance, literal HTML-like/Unicode rendering, a 512-character title, five unique sequential string identifiers within the adapter session, a three-task mixed-state count/filter truth table, completion toggle-back, PATCH title preservation, and three deletions returning the UI to empty. The run passed cross-record/evidence-link integrity and JSON Schema/comparison validation. Its [41-file runtime artifact](https://github.com/REMAREMA6/software-rules/actions/runs/45858743131/artifacts/15136459580) is retained for 30 days.

Six previously partial properties were promoted based on the new evidence. Four additional properties were captured, and the 512-character title result was recorded as partial because the maximum length remains unknown. Two required properties remain partial overall. The updated capture inventories and comparison reports passed the full workflow in [run #45859279008](https://github.com/REMAREMA6/software-rules/actions/runs/45859279008), including integrity and JSON Schema validation.

## Next probes

1. Extend title-boundary probes to determine whether and where an upper title-length limit exists.
2. Title cases: empty, whitespace-only, leading/trailing whitespace, duplicate, long, Unicode, and HTML-like content.
3. State truth table: zero, one, and multiple tasks with mixed completion states; toggle completion in both directions; compare total/active counts and each filter.
4. Operation boundaries: repeated delete, unknown ID, malformed payload, invalid field type, unknown fields, repeated PATCH, and request failure for create/update/delete.
5. Data shape: exact request/response keys, value types, null/missing behaviour, identifier sequence and uniqueness under multiple creates.
6. Evidence quality: attach property-specific evidence locations and make validation reject missing, mismatched, or non-supporting evidence links where machine-checkable.

No unresolved property is to be promoted to captured merely to satisfy CI.


## Supplemental runtime probe result

The expanded harness passed in [run #45860499892](https://github.com/REMAREMA6/software-rules/actions/runs/45860499892). The 65-file [runtime artifact](https://github.com/REMAREMA6/software-rules/actions/runs/45860499892/artifacts/15137373210) contains all three variant captures.

- Reference and independent screenshots matched exactly in 13 states: the original seven, three responsive viewports, focus, hover, and dark colour-scheme preference.
- No horizontal overflow was observed at 320×720, 768×900, or 1920×1080 CSS px.
- SVG-like and script-like titles rendered literally; no SVG, script, or image element was injected and no payload executed.
- Create, update, and delete requests were each forced to return HTTP 503. The errors propagated as page errors; no user-facing recovery UI was observed. A failed update left the checkbox visually checked while the failed delete left the task present.
- One-run performance samples recorded navigation load event end of 8.1–8.9 ms, first paint/FCP of 16 ms, and 14 resources per variant. These are hosted-CI measurements, not production performance claims.

The capture inventory updates are being recorded separately. This run does not close facets absent from the Task Board boundary.
